## 1. 项目与**硬规则**

单仓双子项目：`container/`（L0 容器 APK，Kotlin+原生）+ `kernel/`（L1 Node 内核，可 OTA 热更）。

- 仓库：`lobbowen/dsh-mobile`（**只能改这个**）
- **绝不可碰**：`lobbowen/dsh-supervisor-core`、`lobbowen/dsh-supervisor-launcher`
- **一切以 CI 为准**：不允许本地跑任何测试（`scripts/require-ci.js` 会拒绝，退出码 **86**）
- 允许的本地动作：读写/检索文件、用 GitHub API 提交与合并、**只读**核对
- 内核**只从 OTA 源安装**（ADR-0005）；**APK 不含内核**（有审计强制）

## 4. 已定的架构决定（**不要再讨论**）

1. **单一特权来源 = 自带 ADB 客户端**。删除 Shizuku —— **不保留、不做兜底、不引入 PrivilegeSource 抽象**（只有一个源）。
2. **Device Owner 不能 exec**（无此 API）→ DO 只用于装机/装卸/权限/策略等非 shell 能力。
3. 内核 OTA 单一通道（对象存储）；APK 不含内核。
4. 不追求"完整安卓权限"（Android 没有这种东西）——按能力找**最小够用**的特权来源。

## 6. 工作方法（我踩过的坑，**别重犯**）

1. **提交流程**：`push-gen.cjs <branch> "<单行说明>"` → `ci-generic.cjs <branch> <title> <body>`。
2. **判断 CI 结果必须查最新 run 的 job 结论**（`ghinfo.cjs jobs <runid>`）。
   ⚠️ **不要数日志里的 success 次数** —— 日志会累积多轮输出，我因此差点误判"合并了坏提交"。
3. **两个门禁都绿才合并**（`ci.yml` + `Fast APK`）。我曾只看 `ci.yml` 就合并。
4. **提交说明不要内联进命令行** —— 引号会被 shell 吃掉，我曾连失三次且脚本无任何输出。用文件或 heredoc。
5. **写文件内容不要用模板字符串** —— 反引号会截断字符串，我踩了**三次**。用单引号数组或 heredoc。
6. `push-gen.cjs` **快照整棵树**（parent=main）→ 后续推送会取代之前未合并的分支，记得关掉被取代的 PR。
7. **本设备网络下 `github.com` 不可达**（302 后卡死、0 字节）；`api.github.com` 可达；
   `gh-proxy.com` 可用但**不可信**（APK 是全新安装，签名不匹配系统不会拦 → 装前核对大小）。
8. 纯逻辑一律抽成**不依赖 Android** 的类 + 单测（本会话已这样做了 7 个：下载器/版本比较/状态机/解包/OTA准入/监督策略/ADB 协议与握手）。
